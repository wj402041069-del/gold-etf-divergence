每工作日由 GitHub Actions 抓两份发行人官方文件：**SPDR Gold Shares 官方 Historical Archive**（`Closing Price` + `Tonnes of Gold`）与 **iShares Silver Trust 官方 fund 下载**（`NAV per Share` + `Shares Outstanding`），重算标准化曲线、背离强度 `D` 与四象限散点，在图 1 与图 2 之间保留一张**不做标准化的真实价格参照图**，并在顶部提供「黄金 GLD / 白银 SLV / 金银对照」切换与一张**金银 D 对照图**。全部图表共用一根时间轴，可缩放、可悬停、断网也能看。全程不依赖本地电脑开机，也不需要 TradingView 或任何行情客户端。

## 一、这个系统在监测什么

| 曲线 / 区块 | 含义 | 怎么读 |
|---|---|---|
| 持仓 Z（蓝） | 黄金＝实物持仓**吨数**；白银＝**流通份额（百万份）代理**，各自的滚动 Z-score | 正值＝相对近期均值偏高 |
| 价格 Z（橙） | 黄金＝GLD 收盘价；白银＝**NAV/份代理**，各自的滚动 Z-score | 与蓝线放在**同一坐标**，不用双轴 |
| 参照图（橙线） | **黄金＝GLD 每份份额真实收盘价 USD；白银＝SLV 的 NAV/份**，不做任何标准化 | 位于图 1 与图 2 之间，纵轴是真实美元；核对「背离发生时价格在什么位置」 |
| 背离强度 D | `D = Z(持仓) − Z(价格)` | `D > 0`＝持仓相对价格偏强；黄金 `D > 2` 属历史罕见，白银阈值要更谨慎 |
| 图 2b 金银对照 | 两条 D 同坐标（金色＝黄金、银灰＝白银）＋当前视图相关系数 r | 仅「金银对照」模式显示；都是标准差单位，可以直接比方向 |
| 四象限散点 | 一个点＝一期相对上一期的变化：横轴价格涨跌 %、纵轴持仓增减（黄金 吨 / 白银 百万份） | 竖线左＝跌、横线上＝增持；蓝色左上角「价跌 + 增持」＝越跌越买 |
| 统计卡片 | D / 历史分位 / 价跌期占比 / 相关系数 r / 视图区间 | 每项都有对应大白话解释 |
| 小白说明 | 「这些数字怎么读」面板 | **随视图、频率、品种自动重算**，不是写死的文案 |

它回答的是一个很具体的问题：**价格在跌的时候，ETF 的持仓到底是被赎回、还是有人在逆势接？** 持仓是慢变量（存量），价格由边际资金决定，两者不同步是常态；把二者标准化后相减，才能看出谁相对谁更极端。

加上白银之后还能回答第二个问题：**金银的「持仓相对价格强弱」是不是同步？** 全样本共同 1023 周的相关系数 `r ≈ 0.56` —— 会一起动，但经常不同步，所以才需要一张对照图，而不是只看一条线。

## 二、指标怎么算（Z-score 口径）

### 2.1 定义

```text
Z(x, t) = ( x(t) − mean(x, 最近 N 期) ) / std(x, 最近 N 期)
黄金  D(t) = Z(实物持仓吨数, t) − Z(GLD 收盘价, t)
白银  D(t) = Z(流通份额（百万份）, t) − Z(NAV/份, t)
```

Z-score 把「美元/份」「吨」「百万份」这几种不同量纲，都换算成「离自己近期平均有几个标准差」，因此可以直接放在同一张图上相减，也让**两条不同品种的 D 可以同图比较**。窗口默认：日频 `252` / 周频 `52` / 月频 `36`。两个品种各自在自己的连续序列上算 Z，互不影响。

### 2.2 为什么用滚动窗口，而不是全程标准化

全程标准化会让 2004 年建仓期的极端值把整条曲线压平，且会引入未来数据（look-ahead bias）。滚动窗口只用截至当期的数据，**缩放视图只改变可视区间，不改变任何统计口径** —— 放大到最近 1 年时，Z 值不会重算。

### 2.3 为什么用吨数，而不是 AUM

AUM 是「吨数 × 金价」的美元市值。金价跌 10%，即使一克黄金都没被赎回，AUM 也会自动缩水 10% —— 用它做「持仓」会凭空造出一条与价格同步的假曲线。**实物吨数才是真正的持仓**。

**白银为什么不得不用份额代理**：SLV 官方 `Historical` 表实测只有 `As Of / NAV per Share / Ex-Dividends / Shares Outstanding`，没有逐日 `Tonnes in Trust`，也没有市场收盘价（产品页上的吨数是**当前快照**，不是历史序列）。`Shares Outstanding` 不受银价影响、不是 AUM，与 NAV 同源同交易日，是官方能给出的最干净的持仓代理。实物吨数 ≈ 份额数 × 每份含银量，而每份含银量只因管理费缓慢摊薄（年化约 −0.5%），比申赎波动小两个数量级，52 周滚动 Z-score 基本吸收这个慢趋势 —— **但它依然不是吨数**，所以页面所有单位都写「百万份」。

### 2.4 为什么不用双轴

原始那类图（左轴持仓、右轴金价）把两条轴各自截断到很窄的区间，视觉上可以随意制造或抹平「背离」。本系统统一改用 Z-score 同坐标 + 差值 D，双轴带来的错觉直接消失。

### 2.5 散点为什么用「变化量」

用「持仓水平」对「价格收益率」会产共同趋势造成的伪相关；改用一阶差分（本期吨数 − 上期吨数）后，才是在比较两股力量的**方向**。

## 三、数据源、单位与口径

### 3.0 数据源总表（先看这张）

| 用途 | 来源 | 频率 | 能否替代 |
|---|---|---|---|
| 黄金价格 | SPDR 官方 Historical Archive，列 `Closing Price` | 交易日 | ❌ 主计算依赖 |
| 黄金实物持仓 | **同一份文件**，列 `Tonnes of Gold` | 交易日 | ❌ 主计算依赖 |
| 白银价格代理 | iShares SLV 官方 fund 下载，`Historical` 表 `NAV per Share` | 交易日 | ❌ 白银主计算依赖 |
| 白银持仓代理 | **同一份文件**，`Shares Outstanding` ÷ 1e6（百万份） | 交易日 | ❌ 白银主计算依赖 |
| 全球黄金 ETF 口径 | WGC Goldhub 月度 XLSX | 月 | ✅ 但未用于本系统 |
| 全球白银 ETF 口径 | 无同源日频公开序列 | — | ✅ 未用于本系统 |

### 3.1 为什么选这一份文件

黄金的价格与持仓来自**同一份 XLSX、同一交易日、同一标的（GLD）**；白银的 NAV 与份额数来自**同一份官方 SpreadsheetML、同一交易日、同一标的（SLV）**。两条序列各自同源同频，不存在跨数据源的时点错配。聚合降频时两个品种分别按**同一个周键 / 月键**对齐，避免「价格用收盘、持仓用隔日结算」这类隐性错配。

两份文件都没有任何密钥，`download()` 拉 xlsx、`download_slv()` 拉 SpreadsheetML XML；后者官方 `HRef` 属性里有未转义的裸 `&`，解析前先用正则规范化，否则 XML 解析器会报 `not well-formed`。

### 3.2 交易日 vs 结算日

SPDR 官网提示：Gold Bar List 按 **settlement date**，网站 Trust 数据按 **trade date**，两者可能差一天。本系统只用 Historical Archive 的 `Tonnes of Gold` 列（交易日口径），不混用金条清单。

### 3.3 明确排除项

- ❌ 黄金不用 AUM / 基金规模 / Shares Outstanding 代替吨数
- ❌ **不把白银的 `Shares Outstanding` 标成「吨」**，不把 `NAV per Share` 标成「市场收盘价」或「现货银价 USD/oz」
- ❌ 不用 `Total Ounces of Gold in the Trust` 与 `Tonnes of Gold` 混算（单位不同）
- ❌ 不导入外部 CSV 到 TradingView（TradingView 不支持）
- ❌ 跳过 `US Holiday` 等非交易行；只保留 `price > 0 && tonnes > 0` 的有效行
- ❌ 不把 GLD 单只基金的结论外推成「全球黄金 ETF」

### 3.5 白银代理口径的可信边界

| 说法 | 对不对 |
|---|---|
| 「白银持仓 = 558.65 吨」 | ❌ 错。是 **558.65 百万份**，不是吨 |
| 「份额数就是 AUM」 | ❌ 错。AUM = 份额 × 价格，会随银价自动缩水；份额数不会 |
| 「份额数 ≈ 实物吨数趋势」 | ✅ 基本对。每份含银量只被管理费缓慢摊薄，比申赎波动小两个数量级 |
| 「白银 NAV = 收盘价」 | ❌ 不准确。NAV 是基金净值，与二级市场成交价可能有折溢价 |
| 「白银 D 可以和黄金 D 同图比」 | ✅ 对。两条都是标准差单位，这正是图 2b 的前提 |
| 「黄金 +2 和白银 +2 一样罕见」 | ❌ 不对。白银 D 的历史分布更宽，同样的数值对应不同分位 |

页面在切到白银时会把**标题、副标题、醒目提示、参照图说明、散点轴标签、悬停浮层、口径说明折叠区**全部换成代理口径措辞，避免读者把「份额」误读成「吨」。

### 3.6 为什么用黄金当统一时间轴

白银 2006-04 才上市，比黄金晚约 1.5 年。实测**白银的所有周键都是黄金周键的子集**（白银不在黄金里的周：`0`；黄金不在白银里的周：`74`），所以不需要建第二套视图状态：

```text
master axis = aggregate(GLD, freq)          // 周频 1148 期
aggS        = alignAgg(SLV, aggG, freq)     // 按周一键 / 月键映射，前 74 周填 null
S.resG      = analyze(aggG, 52)
S.resS      = analyze(aggS, 52)             // 含 null 的窗口直接不出 Z，不用 0 / 前值填充
S.view      = 三个模式共用，切品种不重置
```

`analyze()` 算散点变化量时用「上一期**有效**值」，跳过缺口，保证白银散点与它自己的连续序列口径一致（实测白银 D 仍为 `+2.19` / `87.7%`）。对照图里 2006-04 之前只有黄金线，那是**数据缺口不是 D = 0**。

### 5.4 图 3 到底在画什么

这是全页最容易看懵的一张图，单独说清楚：

| 元素 | 含义 |
|---|---|
| 一个点 | **某一期（日 / 周 / 月）相对上一期的变化**，不是那天的金价，也不是那天的持仓总量 |
| 横轴 x | `(本期价格 / 上期价格 − 1) × 100`，单位 %；`x < 0` 在竖线左边＝跌，`x > 0` 在右边＝涨 |
| 纵轴 y | 黄金＝`本期吨数 − 上期吨数`（单位吨）；白银＝`本期份额 − 上期份额`（单位百万份）；`y > 0` 在横线上边＝增持，`y < 0` 在下边＝减持。切品种时轴标签一起变 |
| 蓝色左上角 | 「价跌 + 增持」＝越跌越买，本页重点；底色浅蓝、点更大更蓝 |
| 灰点 | 另外三种情况：右上追涨、左下跌了赎回、右下逢高兑现 |
| 橙色虚线 | 最小二乘拟合的趋势线，越往右上倾斜说明「价涨、持仓也增」越常见，对应 `r` |
| 紫圈 + 紫色细线 | **当前视图末尾 N 期**（默认 10）的轨迹，按时间先后连接，末端空心圈标「最新」；填充色仍表示象限，紫圈只表示「最近」 |
| 显示裁剪 | 按当前视图 2–98 分位裁掉极端值，避免把图压扁；最近 N 期会强制纳入范围不被裁掉；**统计仍用视图内全样本**，所以图上可见点数会略少于卡片里的期数 |

卡片里的「价跌期 / 其中增持」就是这张图的统计版：横轴左半边的点数，以及其中同时落在上半边的点数。悬停任意点会显示具体是哪一期、价格涨跌 %、持仓增减量（黄金 吨 / 白银 百万份）。

**为什么要高亮最近几期**：散点图把上百期压成一团点，**丢掉了时间维度** —— 你能看出「历史上越跌越买出现过多少次」，却看不出「最近还在不在越跌越买」。高亮末尾 N 期并按时间连线，才能回答当下的问题。取的是当前视图（导航条蓝框右端）末尾的 `vs.pts.slice(-N)`，不是导航条上画的点（导航条画的是 D 序列）。

**为什么用描边而不是整点换色**：蓝色已经表示「越跌越买」、灰色表示「其余」、橙色虚线表示趋势线。若再拿一种填充色表示「最近」，读者会分不清某点变蓝是因为象限还是因为时间。因此**填充色保留象限语义，紫色描边 + 连线专门编码时间**，两个维度互不干扰。此外只换颜色仍看不出先后顺序，连成短轨迹才能看出方向。

### 5.5 参照图（图 1 与图 2 之间）为什么这么画

| 决策 | 原因 |
|---|---|
| 用 `res.a[i].p` 原始价格，**不做 Z-score** | 黄金＝GLD 收盘价、白银＝NAV/份。图 1 / 图 2 全是标准化后的相对量，看不出「背离发生时价格到底是 45 还是 350 美元」。加一张真实价格图，才能把统计结论落回现实价位。 |
| **单轴**，不加持仓第二条线 | 价格（USD/份）与吨数 / 百万份量纲不同，加第二条线必然要双轴 —— 正是本项目一开始就规避的视觉陷阱。持仓真实值在悬停浮层里已给出。 |
| 竖带与图 1 共用 `strongSegs()` | 两图 `|D| > 1.5σ` 的时段必须像素级一致，否则对照时会错位。 |
| `L=52 / R=18` 与图 1、图 2、图 2b 相同 | 四图的 `X(i)` 完全一致，hover 竖线才能对齐到同一像素；左边距不同会造成视觉错位。 |
| Y 轴用 `niceNum()` 取 `1/2/5 × 10ⁿ` 刻度 | 避免出现 `312.37` 这类标签；刻度是真实美元，不是标准差。 |
| 纵轴默认自适应 + 可切「从 0 起」 | 自适应方便看短期波动，但截断刻度会放大涨跌观感 —— 图上强制标出范围，并给一键切回零基线的办法。 |
| 复用 `axisX()` / `bindChart()` / `showHover()` | 同一套时间轴驱动：滚轮缩放、拖拽平移、双击重置、导航条框选、悬停全部同步，不存在第二份视图状态。`drawPrice` 遇 `null` 会断线，白银早期缺口不会被画成 0。 |

**黄金口径提醒**：这是 **GLD 每份份额的收盘价（USD/份）**，跟随现货金价但**不等于现货金价 USD/oz**（每份大致对应十分之一盎司，且逐年扣管理费），不要拿它换算吨数或现货价。全历史区间 `41.26 ~ 495.90 USD`，数据末期 `354.89 USD`（2026-11-12）。

**白银口径提醒**：切到白银后画的是 **SLV 的 NAV/份**，是基金净值，**不是二级市场收盘价、也不是现货银价 USD/oz**；不要拿它算金银比价。

### 5.6 品种切换与金银 D 对照（图 2b）

| 模式 | 上方图 1 / 参照图 / 图 2 / 图 3 / 卡片 | 图 2b | 典型用途 |
|---|---|---|---|
| **黄金 GLD**（默认） | 黄金全套，吨 + 收盘价 | 隐藏 | 看金价跌的时候实物黄金被赎回还是被接 |
| **白银 SLV** | 白银全套，百万份 + NAV/份 | 隐藏 | 看银价与份额申赎是否背离 |
| **金银对照** | **仍是黄金**（主品种） | 显示：黄金 D + 白银 D + 当前视图 r | 看两个品种的「承接力度」是不是同步 |

关键点：

1. **统一 master axis**：三个模式共用 `aggregate(GLD, freq)` 的长度（周频 1148 期）和同一个 `S.view`。白银按周键 / 月键对齐进来，早期 74 周填 `null`，所以**切品种不会重置缩放、平移、框选结果**。
2. **两条 D 才能同图比**：`Z` 抹掉了吨 / 百万份 / 美元的量纲，剩下「相对自己历史有几个标准差」。图 2b 的金色线是黄金 D、银灰线是白银 D，右上角 `r` 是**当前视图**的 Pearson 相关系数（全样本共同 1023 周约 `0.56`）。
3. **早期空白不是 D = 0**：2006-04 之前只有黄金线；而且两条线的滚动窗口都要填满 52 期才出值，所以黄金线本身也比页面起点晚约 52 期。这是诚实的缺口，脚本不会用 0 或前值补。
4. **颜色语义**：金色 / 银灰只表示品种；图 1 的蓝 / 橙、图 3 的紫圈各有独立含义，互不复用。
5. **阈值不能照搬**：白银 D 的历史分布比黄金宽，`+2` 在白银对应约 `87.7%` 分位、在黄金对应更靠后。切到白银时页面会追加一句「经验门槛要更谨慎地解释」。

### 5.7 容易误会的地方（黄金模式五条，对照模式另加第六条）

1. **全历史口径 vs 当前视图口径**混用 —— 缩放后卡片数字变了是正常的，不是算错。
2. **持仓是存量、不是流量** —— 「增持」看的是吨数变化，不是申购金额，也不代表所有人都在买。
3. **背离 ≠ 涨跌预测** —— D 只说明两股力量不同步，不构成方向判断。
4. **图 3 的点不是水平值** —— 拿某天的金价或持仓总量去对号入座，一定会读错象限。
5. **参照图不是 Z-score，也不等于现货金价 / 银价** —— 它纵轴是真实美元，且默认按视图自适应；看绝对涨幅请切「从 0 起」。
6. **（新增）白银的「持仓」是份额不是吨** —— 页面所有单位都写「百万份」，别把它当成实物白银吨数，也别和黄金的吨数直接比大小。

## 六、GitHub Actions 部署与定时

| cron（UTC） | 含义 | 作用 |
|---|---|---|

### 6.1 仓库空间治理

- **零空提交**：`window.GLD_UPDATED` / `window.SLV_UPDATED` 存的都是「数据截止日」而不是脚本运行时间。官方没出新数据时，两次运行 `index.html` / `gld_data.csv` / `slv_data.csv` / `llms.txt` 字节完全一致，`git diff --cached --quiet` 成立 → 跳过 commit（Pages 也不会重复构建）。这是防止仓库长期膨胀的关键。
- **触发式清理**：每次运行用 `gh api repos/... --jq '.size'` 查体积，超过 `204800 KB`（200 MB）即压缩。
- **定时清理**：每月 1 日无条件压缩。
- **压缩方式**：`git checkout --orphan` → 单 commit → `git push --force origin main`。`concurrency` 组 `gld-slv-repository` 防并发冲突。
- **提速**：`actions/checkout@v4` 用 `fetch-depth: 1`；依赖锁 `openpyxl==3.1.5`。

> ⚠️ 若给 `main` 开了分支保护，`force push` 会被拒。需要给 `github-actions[bot]` 放行或关闭保护；正常情况下压缩一年只发生 12 次。

## 九、防 Bug 铁律（改动代码前必读）

1. **不要在数据块里写运行时间** —— 会导致无新数据也天天提交，仓库持续膨胀。
2. **不要改 `newline="\n"` 与 `csv.writer(..., lineterminator="\n")`** —— Windows 写回 CRLF 会让 Actions/Linux 首次运行产生整文件 diff；`index.html` / `llms.txt` / 两份 CSV 统一 LF，避免跨平台换行符制造无意义提交。
3. **不要在数据块标记之外插入同名标记** —— `update_html()` 用正则 `count=1` 替换，第二个标记会截断数据。
4. **拖拽平移分支里的 `rect` 必须自己取** —— 它只在散点分支赋值，图 1 / 参照图 / 图 2 直接引用会抛 `TypeError`（已修为局部 `drect`）。
5. **不要用 AUM 代替吨数**，不要用双轴，不要用「持仓水平」做散点纵轴；**也不要把白银的份额数标成吨、把 NAV 标成收盘价**。
6. **缩放只改可视区间** —— 任何在 `clampView` / `render` 里重算 Z-score 的改动都是错的。
7. **负相关时说明文案要跟着变** —— `renderExplain` 里的 `rDetail` 不能写死「价格涨持仓也增」。
8. **压缩历史用 orphan branch，不要 `--amend` 每次提交** —— 后者会让 Actions 与本地长期分叉。
9. **`llms.txt` 不许手改，口径必须与页面一致** —— `write_llms()` 里的 `weekly()`（周一为 key、同周取最后交易日）与 `roll_z()`（总体标准差，除以 `n`）是照抄 `index.html` 的 `aggregate` / `rollZ`；改了一边就必须改另一边，否则给 AI 的摘要会和页面读数打架。
10. **四个产物必须同批提交** —— `index.html` / `gld_data.csv` / `slv_data.csv` / `llms.txt`，漏一个就会出现「页面是新的、摘要是旧的」；`update.yml` 的 `git add` 必须列全。
11. **改完必须验证**：`node --check` 三段脚本 + 浏览器端渲染 / 三品种切换 / hover / 缩放 / 拖拽 / 框选（**四图竖线必须对齐到同一期**），以及 `python fetch_and_build.py` 连续两次运行四个产物哈希一致。
12. **四张时间序列图必须共用一套时间轴状态** —— 新加任何时间序列图，都要复用 `axisX()` / `bindChart(..., kind)` / `showHover()` / `clearHover()` 和同一个 `S.view`，不要另建视图或独立缩放状态；`drawPrice` / `drawCompare` 的 `L` / `R` 与 `drawZ` / `drawD` 必须一致（`52 / 18`），否则 hover 竖线像素错位。
13. **参照图绝不能标准化** —— 它画的是 `res.a[i].p` 原始 USD 价格（黄金收盘价 / 白银 NAV）。换成 Z-score / 对数收益 / 归一化都会让这张图失去意义；纵轴范围必须在图上标出，且提供「从 0 起」避免截断刻度误导。
14. **两个数据块的标记不能重名或嵌套** —— `__GLD_DATA_START__/__END__` 与 `__SLV_DATA_START__/__END__` 各自被 `update_html()` / `update_slv_html()` 用 `count=1` 的非贪婪正则替换；少一个标记脚本直接报错，多一个会截断数据。
15. **白银缺口必须用 `null`，不能用 0 / 前值填充** —— `rollZ()` 遇含 `null` 的窗口返回 `null`，`analyze()` 的变化量用「上一期有效值」，`drawPrice()` 遇 `null` 断线。任何把它补成 0 的改动都会在 2006-04 之前画出假数据。
16. **三个模式共用 `S.view`，切品种不要调 `build()` / `defaultView()`** —— 只允许换 `S.res` + `applyMode()` + `render()`；否则用户缩放好的区间会被重置，且对照图与主图对不上。
17. **`U()` 是唯一的口径出口** —— 页面里所有「吨 / 百万份 / 收盘 / NAV」文字都要走 `SPEC` 或 `applyMode()`，不要在图函数里硬编码黄金单位；`compare` 模式的主品种是黄金（`U()` 返回 `gold`），对照图单独取 `S.resS`。
18. **白银是独立分支，失败不能阻断黄金** —— `main()` 里 SLV 用 `try/except` 包住并回读 `slv_data.csv`；不要把两个下载合并成一次请求或让白银异常抛出主流程。

## 十、常见问题 FAQ

**Q：为什么默认只显示近 3 年？**
20 年全周期下最近几个月会被挤成几个像素。用「近 1 年」按钮或滚轮放大即可；统计口径不会因此变化。

**Q：卡片数字和我上次看到的不一样？**
`D` 与「历史分位」是全历史口径，缩放不变；「价跌期 / 其中增持」「r」「视图区间」随视图变。切换频率（日/周/月）也会改变读数。

**Q：能不能做成实时？**
不能，也没必要。官方档案一天只追加一行 T-1 数据，日内刷新只会重复抓同一份文件。

**Q：TradingView 里能不能直接画？**
TradingView 没有全球黄金 ETF 实物持仓吨数曲线，也不支持导入外部 CSV。用本仓库的 `gld_data.csv` 自己画是最准的路径。

**Q：参照图那条橙线，和图 1 里的橙色「价格 Z」有什么区别？**
同一份 GLD 收盘价，两种画法。参照图是**原始美元**：纵轴 200 就是 200 美元，能看出绝对价位和涨了多少美元；图 1 的橙色线是它的**滚动 Z-score**：0＝等于近期均值、+2＝少见地高，用来和蓝色的持仓 Z 在同一坐标里相减得到 D。判断背离看图 1 / 图 2，确认「当时金价到底多少」看参照图。

**Q：参照图的纵轴为什么默认不是从 0 开始？会不会骗人？**
默认「自适应」是为了让近 3 年的波动看得清，但截断刻度确实会放大涨跌观感 —— 这正是本项目一直提醒的陷阱。所以图上会写明纵轴范围，并给了「从 0 起」按钮：想看长期真实幅度，一键切过去即可。两张图看下来才不会被刻度带偏。

**Q：参照图能当现货金价用吗？**
不能。黄金模式是 **GLD 每份份额价格（USD/份）**，大致对应十分之一盎司且逐年扣管理费，与现货金价 USD/oz 不是同一个数；白银模式是 **SLV 的 NAV/份**，既不是收盘价也不是现货银价 USD/oz。都不要互相换算或算金银比价。

**Q：白银有数据吗？和黄金一样吗？**
有，但**不一样**。白银用 iShares Silver Trust (SLV) 官方 fund 下载，5,175 个交易日（2006-04-21 起）。黄金那份官方 XLSX 同时给 `Closing Price` 与 `Tonnes of Gold`；SLV 官方 `Historical` 表只给 `NAV per Share` 与 `Shares Outstanding`，**没有逐日实物吨数、也没有市场收盘价**。所以白银采用代理口径，页面会全程标注「百万份 / NAV」，绝不混写成吨。

**Q：为什么白银用「份额数」代理持仓，靠得住吗？**
份额数是官方同日披露的真实申赎结果，不受银价影响、不是 AUM。实物吨数 ≈ 份额数 × 每份含银量，后者只因管理费缓慢摊薄（年化约 −0.5%），比申赎波动小两个数量级，52 周滚动 Z-score 基本吸收这个慢趋势，所以 `D` 的形状仍可解读。但**它不是吨数**，也不能与黄金吨数比绝对值。

**Q：能把黄金的 354.89 USD 和白银的 45.96 USD 直接比吗？能把 1040 吨和 558 百万份比吗？**
都不能。两只基金每份份额对应的金属含量、价格口径、持仓单位全不同。**唯一可跨品种比较的是标准化后的 `Z` 与 `D`**（以及变化率），这正是图 2b 只画两条 D 线的原因。

**Q：为什么金银对照图前几年只有一条线？是数据丢了吗？**
不是。白银 2006-04 才上市，黄金 2004-11 就有数据，早期 74 周白银留空；另外两条 D 都要等 52 期滚动窗口填满才出值，所以黄金线本身也比页面起点晚约 52 期。空白＝**数据缺口**，不是 `D = 0`，脚本不会用 0 补。

**Q：切品种会把我刚缩放好的时间范围重置吗？**
不会。三个模式共用同一根黄金 master axis 和同一个 `S.view`，切品种只换数据系列和文案，缩放 / 平移 / 框选结果原样保留。

**Q：在线地址打不开 / 看到的是旧数据？**
`github.io` 在国内偶尔不可达，可下载仓库根目录 `index.html` 本地打开，内容完全一致（见开头「离线快照」）。Pages 有 CDN 缓存，刷新后等约 1 分钟，或加 `?v=<时间戳>` 强刷；页面标题旁的「数据截至 YYYY-MM-DD」才是真实数据日。

**Q：`llms.txt` 是干什么的？**
给 AI / 大模型读的纯文本摘要：数据截止日、最新读数、口径、限制、链接一页说完。问 AI 时发这个链接比发网页省事得多；它由脚本自动生成，**不要手改**。

**Q：Actions 跑了但没新 commit？**
正常 —— 说明官方还没出新的交易日数据，脚本判定字节无变化后跳过提交（Pages 也不会重复构建）。

## 十一、已知限制与免责声明

- **GLD / SLV 都是单只基金**，不是全球黄金 / 白银 ETF 总持仓；与 WGC Goldhub 的「全球 100+ 只 ETF、月度、吨」口径覆盖范围不同，**两者不可互推**。
- **白银是份额代理口径**：`Shares Outstanding`（百万份）不是实物吨数，`NAV per Share` 不是市场收盘价；与黄金的实物吨数 / 收盘价**绝对值不可比**。
- 参照图画的是 **份额价格（黄金 GLD 收盘价 / 白银 SLV NAV，USD/份）**，不是现货金价 / 银价 USD/oz，也不是伦敦金定盘价；不要拿它做跨市场比价或换算金银比价。
- **金银 D 相关系数 `r`** 只描述「持仓相对价格强弱」的同向程度，不代表两只基金价格同步，更不代表因果；白银 D 分布更宽，阈值解释要更谨慎。
- Z-score 是相对自身历史的统计描述，不是买卖信号；`D` 大不代表价格即将反转。
- 相关系数只说明同向程度，不说明因果。
- 2004–2005 年建仓期持仓吨数快速爬升，属结构性变化，不宜与成熟期直接比较。
- 原始数据版权归发行人所有，原始 XLSX / SpreadsheetML 含使用限制且未入库；本仓库只发布衍生指标页面与两份三列 CSV，**公开可见性及由此产生的授权责任由仓库所有者自行承担**，如权利方有异议请联系移除。
