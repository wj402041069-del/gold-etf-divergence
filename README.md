# 黄金 ETF 价格 × 持仓量背离监测系统：20 年同源日频 · 滚动 Z-score · 三图联动 · 小白解读

每工作日由 GitHub Actions 从 **SPDR Gold Shares 官方 Historical Archive** 抓取同一份 XLSX，取出 `Closing Price` 与 `Tonnes of Gold`，重算标准化曲线、背离强度 `D` 与四象限散点，产出可缩放、可悬停、断网也能看的离线看板。全程不依赖本地电脑开机，也不需要 TradingView 或任何行情客户端。

## 一、这个系统在监测什么

| 曲线 / 区块 | 含义 | 怎么读 |
|---|---|---|
| 持仓 Z（蓝） | 实物持仓**吨数**的滚动 Z-score | 正值＝相对近期均值偏高 |
| 价格 Z（橙） | GLD 收盘价的滚动 Z-score | 与蓝线放在**同一坐标**，不用双轴 |
| 背离强度 D | `D = Z(持仓) − Z(价格)` | `D > 0`＝持仓相对价格偏强；`D > 2` 属历史罕见 |
| 四象限散点 | 横轴价格收益率、纵轴持仓变化 | 左上「价跌 + 增持」＝越跌越买 |
| 统计卡片 | D / 历史分位 / 价跌期占比 / 相关系数 r / 视图区间 | 每项都有对应大白话解释 |
| 小白说明 | 「这些数字怎么读」面板 | **随视图、频率自动重算**，不是写死的文案 |

它回答的是一个很具体的问题：**金价在跌的时候，ETF 的实物黄金到底是被赎回、还是有人在逆势接？** 持仓是慢变量（存量），价格由边际资金决定，两者不同步是常态；把二者标准化后相减，才能看出谁相对谁更极端。

## 二、指标怎么算（Z-score 口径）

### 2.1 定义

```text
Z(x, t) = ( x(t) − mean(x, 最近 N 期) ) / std(x, 最近 N 期)
D(t)    = Z(持仓吨数, t) − Z(收盘价, t)
```

Z-score 把「美元/股」和「吨」两种不同量纲，都换算成「离自己近期平均有几个标准差」，因此可以直接放在同一张图上相减。窗口默认：日频 `252` / 周频 `52` / 月频 `36`。

### 2.2 为什么用滚动窗口，而不是全程标准化

全程标准化会让 2004 年建仓期的极端值把整条曲线压平，且会引入未来数据（look-ahead bias）。滚动窗口只用截至当期的数据，**缩放视图只改变可视区间，不改变任何统计口径** —— 放大到最近 1 年时，Z 值不会重算。

### 2.3 为什么用吨数，而不是 AUM

AUM 是「吨数 × 金价」的美元市值。金价跌 10%，即使一克黄金都没被赎回，AUM 也会自动缩水 10% —— 用它做「持仓」会凭空造出一条与价格同步的假曲线。**实物吨数才是真正的持仓**。

### 2.4 为什么不用双轴

原始那类图（左轴持仓、右轴金价）把两条轴各自截断到很窄的区间，视觉上可以随意制造或抹平「背离」。本系统统一改用 Z-score 同坐标 + 差值 D，双轴带来的错觉直接消失。

### 2.5 散点为什么用「变化量」

用「持仓水平」对「价格收益率」会产共同趋势造成的伪相关；改用一阶差分（本期吨数 − 上期吨数）后，才是在比较两股力量的**方向**。

## 三、数据源、单位与口径

### 3.0 数据源总表（先看这张）

| 用途 | 来源 | 频率 | 能否替代 |
|---|---|---|---|
| 收盘价 | SPDR 官方 Historical Archive，列 `Closing Price` | 交易日 | ❌ 主计算依赖 |
| 实物持仓 | **同一份文件**，列 `Tonnes of Gold` | 交易日 | ❌ 主计算依赖 |
| 全球黄金 ETF 口径 | WGC Goldhub 月度 XLSX | 月 | ✅ 但未用于本系统 |

### 3.1 为什么选这一份文件

价格与持仓来自**同一份 XLSX、同一交易日、同一标的（GLD）**，天然同源同频，不存在跨数据源的时点错配。聚合降频时两条序列一起处理，避免「价格用收盘、持仓用隔日结算」这类隐性错配。

### 3.2 交易日 vs 结算日

SPDR 官网提示：Gold Bar List 按 **settlement date**，网站 Trust 数据按 **trade date**，两者可能差一天。本系统只用 Historical Archive 的 `Tonnes of Gold` 列（交易日口径），不混用金条清单。

### 3.3 明确排除项

- ❌ 不用 AUM / 基金规模 / Shares Outstanding 代替吨数
- ❌ 不用 `Total Ounces of Gold in the Trust` 与 `Tonnes of Gold` 混算（单位不同）
- ❌ 不导入外部 CSV 到 TradingView（TradingView 不支持）
- ❌ 跳过 `US Holiday` 等非交易行；只保留 `price > 0 && tonnes > 0` 的有效行
- ❌ 不把 GLD 单只基金的结论外推成「全球黄金 ETF」

### 3.4 实测锚点

```text
数据区间     2004-11-18 ~ 2026-11-11，共 5529 个有效交易日
最新读数     收盘 365.17 USD / 持仓 1041.08 吨
周频结果     D = +1.14（历史 90.4% 分位），聚合 1148 期，窗口 52
日频 / 月频  D = +1.09（89.5%）/ +0.36 —— 结论对频率敏感，切换时不要混比
官方节奏     Last-Modified 约 04:10 UTC 追加 T-1 数据，CDN s-maxage=86400
```

### 5.3 小白说明面板

五段解释与卡片一一对应，且**跟着视图自动重算**：`D` 与「历史分位」按全历史算（缩放不变），「价跌期 / 其中增持」「相关系数 r」「视图区间」随当前视图变。面板底部另写明 Z-score 白话定义与「三个容易误会的地方」。

### 5.4 三个容易误会的地方

1. **全历史口径 vs 当前视图口径**混用 —— 缩放后卡片数字变了是正常的，不是算错。
2. **持仓是存量、不是流量** —— 「增持」看的是吨数变化，不是申购金额，也不代表所有人都在买。
3. **背离 ≠ 涨跌预测** —— D 只说明两股力量不同步，不构成方向判断。

## 六、GitHub Actions 部署与定时

| cron（UTC） | 含义 | 作用 |
|---|---|---|
| `13 6 * * 1-5` | 每工作日 06:13 | 主抓（官方约 04:10 更新，避开整点排队） |
| `13 9 * * 1-5` | 每工作日 09:13 | 补抓，仅在主抓失败 / CDN 缓存延迟时起作用 |
| `37 3 1 * *` | 每月 1 日 03:37 | 定时压缩提交历史 |

`workflow_dispatch` 支持手动触发，附 `force_compact` 布尔选项可顺便强制压缩历史。

### 6.1 仓库空间治理

- **零空提交**：`window.GLD_UPDATED` 存的是「数据截止日」而不是脚本运行时间。官方没出新数据时，两次运行 `index.html` / `gld_data.csv` 字节完全一致，`git diff --cached --quiet` 成立 → 跳过 commit。这是防止仓库长期膨胀的关键。
- **触发式清理**：每次运行用 `gh api repos/... --jq '.size'` 查体积，超过 `204800 KB`（200 MB）即压缩。
- **定时清理**：每月 1 日无条件压缩。
- **压缩方式**：`git checkout --orphan` → 单 commit → `git push --force origin main`。`concurrency` 组 `gld-repository` 防并发冲突。
- **提速**：`actions/checkout@v4` 用 `fetch-depth: 1`；依赖锁 `openpyxl==3.1.5`。

> ⚠️ 若给 `main` 开了分支保护，`force push` 会被拒。需要给 `github-actions[bot]` 放行或关闭保护；正常情况下压缩一年只发生 12 次。

### 6.2 权限与密钥

```yaml
permissions:
  contents: write
```

使用平台自动注入的 `GITHUB_TOKEN`，提交身份为 `github-actions[bot]`。**仓库内不需要、也不应存放任何 PAT**。个人访问令牌只在首次建仓 / 本机推送时使用，用完请立即在 GitHub Settings → Developer settings 撤销。

## 九、防 Bug 铁律（改动代码前必读）

1. **不要在数据块里写运行时间** —— 会导致无新数据也天天提交，仓库持续膨胀。
2. **不要改 `newline="\n"`** —— Windows 写回 CRLF 会让 Actions/Linux 首次运行产生整文件 diff。
3. **不要在数据块标记之外插入同名标记** —— `update_html()` 用正则 `count=1` 替换，第二个标记会截断数据。
4. **拖拽平移分支里的 `rect` 必须自己取** —— 它只在散点分支赋值，图 1/图 2 直接引用会抛 `TypeError`（已修为局部 `drect`）。
5. **不要用 AUM 代替吨数**，不要用双轴，不要用「持仓水平」做散点纵轴。
6. **缩放只改可视区间** —— 任何在 `clampView` / `render` 里重算 Z-score 的改动都是错的。
7. **负相关时说明文案要跟着变** —— `renderExplain` 里的 `rDetail` 不能写死「价格涨持仓也增」。
8. **压缩历史用 orphan branch，不要 `--amend` 每次提交** —— 后者会让 Actions 与本地长期分叉。
9. **改完必须验证**：`node --check` 两段脚本 + 浏览器端渲染 / hover / 缩放 / 拖拽 / 框选，以及 `python fetch_and_build.py` 连续两次运行哈希一致。

## 十、常见问题 FAQ

**Q：为什么默认只显示近 3 年？**
20 年全周期下最近几个月会被挤成几个像素。用「近 1 年」按钮或滚轮放大即可；统计口径不会因此变化。

**Q：卡片数字和我上次看到的不一样？**
`D` 与「历史分位」是全历史口径，缩放不变；「价跌期 / 其中增持」「r」「视图区间」随视图变。切换频率（日/周/月）也会改变读数。

**Q：能不能做成实时？**
不能，也没必要。官方档案一天只追加一行 T-1 数据，日内刷新只会重复抓同一份文件。

**Q：TradingView 里能不能直接画？**
TradingView 没有全球黄金 ETF 实物持仓吨数曲线，也不支持导入外部 CSV。用本仓库的 `gld_data.csv` 自己画是最准的路径。

**Q：为什么仓库是 Private / 没有在线网址？**
见开头说明：SPDR 数据禁止再分发，`index.html` 内含逐日明细。本地双击打开功能完全一致。

**Q：Actions 跑了但没新 commit？**
正常 —— 说明官方还没出新的交易日数据，脚本判定字节无变化后跳过提交。

## 十一、已知限制与免责声明

- **GLD 是单只基金**，不是全球黄金 ETF 总持仓；与 WGC Goldhub 的「全球 100+ 只 ETF、月度、吨」口径覆盖范围不同，**两者不可互推**。
- Z-score 是相对自身历史的统计描述，不是买卖信号；`D` 大不代表价格即将反转。
- 相关系数只说明同向程度，不说明因果。
- 2004–2005 年建仓期持仓吨数快速爬升，属结构性变化，不宜与成熟期直接比较。
- 原始数据版权归发行人所有，禁止再分发；本仓库仅供个人研究，**不构成投资建议**。

## 十二、给 AI 的维护提示词

### 12.1 仓库速览：哪个文件能改、改了会炸什么

| 文件 | 能动 | 改错会怎样 |
|---|---|---|
| `index.html` 数据块 | ❌ | 下次 Actions 全量覆盖，手动改动必丢 |
| `index.html` 其余部分 | ✅ | 改坏计算/交互会白屏或数值错；必须跑浏览器验证 |
| `fetch_and_build.py` | ✅ | 列名定位写错会抛「表头未识别」；时间戳写错会导致空提交刷屏 |
